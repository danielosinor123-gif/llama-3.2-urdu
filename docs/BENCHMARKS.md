# Benchmarks

Benchmark protocol for the Urdu drama-script model. Every result in this repo must be reproducible with the commands below.

## Held-out test set

- Located at `data/final/test.jsonl`, generated by `src/data/build_dataset.py`.
- Splits are **episode-level**: no scene from an episode in train/val ever appears in test. This prevents the most common leak in fine-tuning — the same episode appearing in both train and eval.
- Split assignment is deterministic (MD5 hash of episode id), so anyone rebuilding the dataset gets identical splits.

## Protocol

All evaluation uses:

- **Greedy decoding** (`do_sample=False`) — deterministic, comparable across runs
- **Fixed repetition penalty 1.1**
- **Fixed max_new_tokens** (default 300)
- **Same prompts for baseline and fine-tuned models** — no cherry-picking

```bash
# Fine-tuned model
python src/evaluate.py \
  --model_dir models/urdu-drama-3.2-qLoRA \
  --eval_data data/final/test.jsonl \
  --baseline_model meta-llama/Llama-3.2-3B-Instruct \
  --output reports/eval.json
```

This produces a single JSON report containing both models' scores, enabling direct comparison.

## Metrics

### Automated metrics

| Metric | What it measures | Interpretation |
|---|---|---|
| ROUGE-1/2/L | n-gram overlap with reference script | Weak for creative text — a fluent but different script scores low. Report, don't worship. |
| BLEU (sacrebleu) | Precision-weighted n-gram overlap | Same caveat. Useful for tracking regression between model versions. |
| chrF (sacrebleu) | Character-level F-score | More robust than BLEU for morphologically rich languages like Urdu. |
| Script Structure Score | Fraction of outputs with (a) scene heading, (b) speaker-labeled dialogue, (c) action lines | Domain-specific metric — measures whether the model learned drama *format*, which ROUGE cannot capture. |
| Avg prediction length | Degeneration check | Near-zero or maxed-out length signals collapse or non-termination. |

**Honest note:** for creative generation, n-gram metrics against a single reference are a weak proxy. They are necessary (regression detection) but not sufficient (quality). That is why the layered evaluation exists.

### Structure scoring

`src/evaluate.py:script_structure_score` programmatically checks each output for:

1. Scene headings (`منظر \d`)
2. Speaker labels (`کردار:` pattern)
3. Action lines (parentheticals)

A score of 1.0 means every output is well-formed drama format. The un-finetuned base model will score near 0.

### Qualitative samples

Each eval report includes 5 (prompt, prediction, reference) triples for manual review. Review them for:

- Hindi-leaning vocabulary (Sanskritized words, Devanagari leakage)
- Character voice consistency
- Register (formal vs colloquial as requested by the prompt)
- Scene continuity when given prior scenes

## Stress testing

Run before every training run and after every dataset change:

```bash
python src/stress_test.py --data_dir data/final --seed_dir data/seed
```

Checks (exit code 1 on any failure):

1. **Split leakage** — zero episode overlap between train/val/test
2. **Contamination** — Devanagari codepoints, low Arabic-script ratio, Hindi-ism blocklist
3. **Duplicates** — normalized (punctuation-insensitive) fingerprint uniqueness across all splits
4. **Length outliers** — no degenerate short/long rows
5. **Template repetition** — no single prompt template dominating (diversity check)
6. **Seed script integrity** — required fields present, every dialogue line passes the Urdu filter

Plus unit tests: `python -m pytest tests/ -q`

## Dataset provenance

Every training row records its source. The build report (`data/final/build_report.json`) contains per-source counts and filter/drop statistics. Benchmark results must state which sources were included — a model trained only on seed scripts is not the same model as one trained with subtitle dialogue.
